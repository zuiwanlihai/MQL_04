# 网格 V1 / V2 策略分析与对比

本文依据[公共策略方案分析规则](./公共策略方案分析规则.md)、[策略方案分析规则](./策略方案分析规则.md)、[网格V1](./网格V1.md)和[网格V2](./网格V2.md)逐项对照。

> 口径说明：V1 是对当前项目代码的分析；V2 是优化方案，不是已经实现或验证的策略。以下将“代码已有”“文档建议”和“尚未定义”分开表述。

## 一、按公共规则逐项分析

| 公共规则 | 网格V1：当前实现 | 网格V2：优化方案 | 判断 |
|---|---|---|---|
| 1. 过滤规则 | **无。**不判断趋势、区间、波动率或交易时段。 | 建议 H1；ADX、EMA 斜率作区间过滤，ADX ≥25 或 EMA 变化超阈值时暂停加仓；灰区不加仓。 | V2 有规则框架，但需明确指标计算、灰区阈值及过滤关闭后已有持仓如何处理。 |
| 2. 开仓规则 | M5 收盘价触及锚点下方档位时市价买入，触及上方档位时市价卖出；每个方向每根 K 线最多开一笔。 | 区间过滤通过后，在锚点两侧按档位开仓；每方向最多建议 3 档。 | V1 条件和执行方式明确。V2 未明确触发价格、检查频率、是否市价单及单根 K 线开仓限制。 |
| 3. 平仓规则 | 多仓收盘价 ≥ 实际入场价 + 一格时平仓；空仓收盘价 ≤ 入场价 − 一格时平仓；市价执行。 | 保留每笔盈利一格逐笔止盈。 | 两者均有逐笔止盈；V2 需定义一格距离和触发价格的单位及成交报价口径。 |
| 4. 止损规则 | **无策略止损。**代码说明 MVP 无券商保护单。 | 提出单轮亏损预算触发后平仓，并提到硬止损，但未定义具体价格或计算公式。 | V2 有风险退出意图，但“硬止损”尚未落成可执行规则；1% 风险预算如何计算也未说明。 |
| 5. 止盈规则 | 有，单笔价格有利变动一格后退出；未证明扣除全部成本后恰好净赚一格。 | 同样逐笔一格止盈，要求按实际成交价、可执行报价考虑成本。 | V2 对成交偏差的认识更完整，但尚缺成本覆盖和实际执行定义。 |
| 6. 移动止损规则 | **无。** | **无明确移动止损规则。**趋势增强时停止加仓，不等于移动止损。 | 两者都没有。V2 应说明是否需要，不能把暂停加仓误作持仓止损。 |
| 7. 移动止盈规则 | **无。**逐笔固定目标，不跟踪利润。 | **无明确移动止盈规则。** | 两者都没有。 |
| 8. 最大持仓规则 | 每方向持仓笔数最多 `max_levels`，源码默认每边 5；多空同时满仓时可能合计 10 笔。没有总手数、名义敞口或保证金上限。 | 建议每方向最多 3 档，另建议限制敞口和保证金，但没有给出具体上限或账户级计算方法。 | V2 档数较低，但总风险约束仍需可计算、可执行。 |
| 9. 最大持仓笔数规则 | 明确按方向分别计数；固定每笔 0.1 手是源码默认值，不代表实际实例参数。 | 每档固定手数、每方向 3 档是建议；实际最大总笔数及双向同时持仓规则需写清。 | V1 代码规则更具体；V2 需说明 3 档是每边还是合计，并决定是否允许双向持仓。 |
| 10. 最长持仓规则 | **无。**没有按持仓时长退出或告警。 | **无。**冷却期是退出后的暂停，不是持仓最长时间。 | 两者均缺少最长持仓和到期动作。 |
| 11. 单笔订单手数规则 | 源码默认固定 0.1 手；没有按权益、止损距离或压力亏损计算。实际运行值须查实例参数。 | 要求固定手数，并建议以权益、合约规格和压力情景估算，但没有提供确定手数的公式。 | V2 的风险原则优于 V1，仍需给出输入、计算公式和舍入/最小手数处理。 |
| 12. 周期、价格、检查时机、下单类型及订单异常 | 默认 M5；每根 K 线用收盘价触发，市价开/平。开仓失败会记录日志，平仓失败会警告；未明确部分成交、跳空时风险和未确认订单的统一处置。 | 回测起点建议 H1；实际用什么报价和检查时机、采用市价还是挂单未完全规定。提出订单未确认时保留档位占用，并提及跳空、部分成交、失败等回测检查项，但不是完整的线上处置流程。 | V1 执行细节更明确；V2 需要把风险建议补成具体的订单状态机和失败处理规则。 |
| 13. 最长持仓到期动作 | 不适用/未实现。 | 未定义。 | 两者都需要补充强制平仓、减仓、停加仓或告警的选择及例外。 |
| 14. 风险熔断与异常处理 | 没有亏损熔断、冷却、异常停开仓机制；仅在源码中对下单/平仓失败记录日志。 | 建议单轮损失上限 1%、达到后停止开仓并平仓、冷却；数据异常或状态不明时停止新开仓并告警。冷却时长、重试、平仓失败升级策略、网关断线时的保护尚未定义。 | V2 明显更完整，但 1% 尚属回测建议，且策略端退出无法替代券商端保护单。 |
| 15. 策略适用范围 | 源码默认 EURUSD、M5；逻辑双向。没有限定适用行情、交易时段、品种边界或账户对冲规则。 | 目标为区间网格，建议 H1；依赖 ATR/ADX/EMA 和品种合约信息。尚未列出适用品种、交易时段及不适用条件。 | V2 明确目标市场状态，但仍需明确品种、账户类型和运行边界。 |
| 16. 回测验证与证据来源 | 有档位止盈后可重新开仓的回归测试；它验证状态逻辑，不构成盈利或风险表现验证。没有在文档中给出完整回测区间、成本和样本外指标。 | 规定纳入点差、佣金、滑点、隔夜费、保证金和压力场景，并评估回撤、浮亏、保证金峰值和参数敏感性；但没有实际回测结果，属于待验证方案。 | 两者都没有可据以判断收益的完整结果；V2 给出了更好的验证计划，但不能称为已验证策略。 |

### 网格专属锚点规则

- **V1**：首次启动时用最新报价 `bid` 初始化锚点；状态持久化，重启不重置；源码提供手动重锚能力，但未规定何时允许重锚以及有仓时怎样处置。
- **V2**：建议新轮开始时锚定，只在该轮仓位清空后重设；间距也每轮固定。若突破最外档半格，停止该方向加仓。但“何为新一轮”“部分持仓已止盈后是否仍属于原轮”“超过半格后是否只停开仓还是强制退出”还要明确。

## 二、V1 与 V2 对比

| 对比项 | 网格V1：当前代码 | 网格V2：优化方案 | 评价 |
|---|---|---|---|
| 策略成熟状态 | 已在模板代码中实现，且有局部回归测试 | 设计方案，未见对应实现和完整回测结果 | V1 是“已实现基础版”；V2 是“待细化、待验证方案”。 |
| 市场适应性 | 固定锚点、固定间距，不过滤行情 | 拟用 ADX/EMA 过滤区间，ATR/点差确定网格间距 | V2 思路更适合控制趋势期的新开仓，但只停开仓无法解决既有仓位风险。 |
| 锚点和间距 | 启动时建立锚点，重启恢复；间距按固定 point 参数计算 | 每轮锚定，按 ATR 与点差计算间距且本轮固定 | V2 更自适应；需规定新一轮生命周期及部分平仓时的状态管理。 |
| 开仓方向 | 锚点上下双向开仓 | 保留双向思路，但允许单方向的条件描述不够具体 | 两者都须结合账户净额/对冲规则明确实际双向行为。 |
| 仓位限制 | 每边最多默认 5 笔、每笔默认 0.1 手；无账户风险计算 | 建议每边 3 档、固定手数；增加 1% 单轮压力预算和敞口限制 | V2 风险意识更完整，但手数和上限还不能直接执行。 |
| 出场保护 | 单笔一格止盈，无止损、无持仓时限 | 单笔一格止盈；加入单轮亏损退出、熔断和冷却意图 | V2 的核心改进是整轮风控；硬止损价及损失预算实现细节缺失。 |
| 执行和异常 | 收盘触发市价单，失败有日志/警告，部分成交处理不明确 | 建议处理延迟确认、跳空、失败与断线，但线上流程不完整 | V2 需要定义订单状态、重试、重复下单防护、失败告警和恢复流程。 |
| 验证情况 | 有档位重入测试，不代表策略绩效验证 | 有回测指标清单，无实际结果 | 目前不能据此断言 V2 比 V1 盈利或风险指标更好。 |

## 三、结论与优先补齐项

- **V1 当前可确认的事实**：固定锚点、固定 point 间距、按 M5 收盘触发、双向市价开仓、单笔走一格平仓；没有止损和最长持仓规则。每边的笔数限制不是亏损上限。
- **V2 相对 V1 的主要改进**：加入区间过滤、ATR/点差间距、单轮风险预算、停开仓和冷却的设计，并要求更全面的回测。
- **V2 仍不宜直接编码/实盘的关键缺口**：单笔/整轮硬止损的确切触发条件、1% 风险预算计算公式、手数公式、最长持仓动作、订单与异常处理流程、锚点“轮次”定义，以及明确的适用范围。
- **建议顺序**：先补全 V2 上述可执行定义，再实现与单元测试；最后用含真实成本和样本外数据的回测评估。不要把 V2 的建议阈值当作已验证表现，也不要把 V1 的回归测试当作策略盈利证据。
