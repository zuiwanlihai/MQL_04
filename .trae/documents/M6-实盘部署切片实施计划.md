# M6 实盘部署 + 风控中心 切片实施计划

## Context（为什么做）

M4（回测）、M5（模拟盘）已交付，撮合内核与增量编排已就位。M6 是 PRD 完整闭环的最后一环：把验证过的策略在**真实 MT5 账户**上下单执行，并以「准入闸门 + 事前风控 + 对账 + 自动降级 + 审计」兜住资金安全。

已确认的关键事实（探查结论）：
- **网关零交易能力**：`gateway/app/mt5_client.py` 只有行情/账户/登录，无 order_send/positions_get/orders_get/history_deals。
- **沙箱禁网络**：`backend/app/sandbox/import_hook.py` 白名单拦截 socket/httpx 等，实盘子进程**不能直连网关**，下单必须经 stdin/stdout JSONL RPC 由父进程中转。
- **三态一致落点是信号层**：同一 engine 循环、同一 `_order_gate`、同一 SDK 契约，仅 `mode` 与执行边界不同；实盘成交价=市场真实价，撮合结果本就不该一致。实盘**不维护虚拟 AccountSim**，账户/持仓/权益全部来自网关真实数据（只读镜像）。
- **不存在需新建**：风控规则表、审计表、feature flag/角色鉴权。`ErrorCode.RISK_BLOCKED` 已占位无实现。
- **已有可复用**：MT5Account 模型、PaperManager/paper_runner/paper_engine（实盘直接克隆母本）、RunnerSupervisor、paper API/前端页面模板。

范围（用户已确认）：网关真实交易全链路 + demo 账户端到端验证 + 准入四闸 + 风控中心（账户规则+Kill Switch）+ 对账/自动降级/告警 + 审计日志表。

硬约束（沿用）：MappedAsDataclass 在 DeclarativeBase 前；default_factory；懒加载路由包 Suspense；子进程流上限 1100000；全中文 UI；alembic async 迁移。

## Phase A — 网关交易能力（独立验证：demo 手动下单/平仓/查仓）

**gateway/app/mt5_client.py** 新增（全部走既有单 worker `run()`）：
- `order_send_sync`（市价开仓 + 平仓 + 撤单，返回 retcode/deal/ticket/成交均价）
- `positions_get` / `orders_get` / `history_deals_get`
- **优先级队列**：交易/紧急命令（Kill Switch）插队于行情轮询之前，保障 Kill ≤3s。

**gateway/app/routes/trade.py**（新建，依赖 require_gateway_key）：
- `POST /trade/order`、`POST /trade/close`、`POST /trade/cancel`
- `GET /trade/positions`、`/trade/orders`、`/trade/deals`

**gateway/app/schemas.py**：OrderRequest/CloseRequest/CancelRequest/PositionRow/OrderRow/DealRow/TradeResult。
**retcode→中文映射**：TRADE_RETCODE_* 表（拒单/无效/市场关闭/资金不足等）。

**backend/app/services/gateway_client.py**：对应加 typed 方法 `order_send/close/cancel/positions/orders/deals`。

门禁：网关单测（mock mt5 包）+ demo 账户 curl/脚本跑通开仓→查仓→平仓→查成交。

## Phase B — 实盘 RPC 协议 + LiveEngine（门禁：demo 跑通 buy/close）

**协议**（子进程 ↔ 父进程，JSONL）：
- 子→父：`{"event":"order_request","req_id":uuid,"op":"buy|sell|close","symbol","volume","position_id","comment":"run_id:req_id","bar_time"}`
- 父→子：`{"type":"order_result","req_id":uuid,"success","order_id","filled_price","filled_volume","commission","error_code","error_message","account":{镜像}}`
- 父→子（周期）：`{"cmd":"account"}` 触发推真实账户/持仓镜像。

**backend/app/sandbox/live_runner.py**（克隆 paper_runner）+ **live_engine.py**（克隆 PaperEngine）：
- `LiveContext(BacktestContext)` 覆写 `mode="live"`，`place_order/place_close` 改为发 order_request 并**阻塞等 order_result**（按 req_id 分流，非匹配行 bars/status 入队缓存，返回后处理）。
- 子进程**不实例化 AccountSim**；`get_account/get_positions` 读父进程推来的只读镜像缓存。
- on_order 内再下单 → 嵌套同一等待循环，天然可重入。

**backend/app/services/live/manager.py**（克隆 PaperManager，module=`app.sandbox.live_runner`）：
- `_stream.on_event` 识别 order_request → 置 `h.busy=True`（poll 跳过投 bar）→ 事前风控求值 → 网关 order_send（独立 `LIVE_ORDER_TIMEOUT=8s`）→ `sup.send(order_result)` → 清 busy。风控拒绝/网关失败**同样回 order_result，绝不静默**。
- 子进程 RPC 超时(15s) > 父网关超时；超时后订单状态不确定 → 置 run `reconcile_pending`，由对账收敛，**禁止盲目重试**（comment 携带 req_id 幂等查重）。

**关键坑（必须处理）**：
- Windows 无 SIGALRM，`engine._call` 事后计时——on_bar 内阻塞等 RPC 会误触 `SANDBOX_CALLBACK_TIMEOUT_LIVE=1s`。live payload 用独立 `LIVE_CALLBACK_TIMEOUT`（≥ 单根最大订单数×RPC超时，建议 60s）；1s 保留给回测/模拟。
- 实盘仅 standard 档语义（optimistic 无意义、conservative 需次根），schema 限制。

门禁：live_engine 单测（fake 父进程喂 order_result）+ demo 端到端 buy→成交回报→close。

## Phase C — 事前风控引擎（门禁：命中返回 RISK_BLOCKED 且网关零调用）

**backend/app/services/risk/engine.py**：纯函数求值器，在父进程、发网关前同步执行。
- `models/risk.py`：`risk_rules`（scope global|account|strategy；type daily_max_loss/max_drawdown/max_lot_per_order/max_open_positions/max_exposure/frequency；threshold；action ∈ reject|halt_open_today|close_all_and_stop；enabled）、`risk_events`。
- 求值输入：order_request 参数 + 账户实时镜像（equity/持仓/当日已实现+浮亏）+ 观察期上限 + 真实 free_margin（不足回 INSUFFICIENT_MARGIN）。
- 观察期叠加：`observation_ends_at` 非空时强制 `volume ≤ symbol.volume_min` 且名义占用 ≤ `allocated_capital×capital_cap_pct`（cap_pct 只可下调）。
- 动作联动：reject→RISK_BLOCKED+写 risk_events；halt_open_today→run 置 `no_new_orders`（拒后续 buy/sell，close 放行）；close_all_and_stop→异步 Kill 子流程+触发 Phase E 降级。

门禁：风控求值单测（各规则命中/边界/观察期上限）。

## Phase D — 准入四闸 + 部署向导（门禁：向导端到端 + 放行审计快照）

**backend/app/services/live/admission.py**（策略版本 × MT5 账户维度）：
- 闸1 权限：`LIVE_ENABLED` 且 `mt5_accounts.live_allowed` 且角色∈{admin,trader}（后端接口同样拒绝）。

- 闸4 记录：窗口内无 risk_events 且无沙箱越界（PaperRun.error_code∈SANDBOX_*）。

## Phase E — 对账 / Kill Switch / 自动降级 / 审计

- **对账**：main.py lifespan 独立后台任务（5min），逐活跃账户比对 run.positions 镜像 vs 网关 positions_get；差异→`mt5_accounts.trade_frozen=True`（事前风控全拒）+告警+审计；恢复后呈现差异、**默认不自动平仓**。`startup_sweep` 后立即对账（重启期无保护）。掉线>5min 告警（复用 gateway heartbeat）。
- **Kill Switch**：`POST /live/kill-switch`（二次确认）直接走网关（positions_get→批量 close→orders_get→撤单→CAS 停全部 run→通知），**不进子进程 RPC 路径**，依赖 Phase A 优先级队列保 ≤3s。
- **自动降级**：close_all_and_stop 触发→`live_allowed=False`，仅风控中心 `POST /live/re-admit`（admin+二次确认+复核说明）恢复，全程审计。
- **审计** `models/audit.py` + `services/audit.py` insert 助手（同事务）：ts UTC 毫秒/actor/action 枚举/target/params/result/risk_decision/source_ip/correlation_id/**prev_hash+hash=sha256(prev_hash+canonical_json) 链式防篡改**；链校验日跑；接入绑户/启停/准入放行/风控触发/Kill/对账/配置变更/降级恢复。

门禁：对账差异→冻结→降级联动集成测试 + 审计链完整性测试 + Kill ≤3s 压测（demo）。

## Verification（端到端）

1. 网关：demo 手动 order_send→positions_get→close→history_deals 全通。
2. 后端：`LIVE_ENABLED=true` + demo 账户 live_allowed，向导四闸放行，部署 LiveRun，子进程 buy→父进程风控→网关真实成交→order_result→on_order，持仓镜像刷新。
3. 风控：构造 daily_max_loss 命中→halt_open_today；max_drawdown 命中→close_all_and_stop→自动降级 live_allowed=False→re-admit 恢复。
4. Kill：≤3s 撤单+平仓+停策略。
5. 对账：人为制造差异→trade_frozen+告警+审计，不自动平仓。
6. 审计：链式 hash 校验通过，关键写操作均有记录。
7. 前端：向导/列表/详情/控制/Kill 全链路浏览器 E2E。

## 风险点（Plan agent 复核，必须落地处理）
1. 1s 回调超时误杀阻塞 RPC → 独立 LIVE_CALLBACK_TIMEOUT。
2. 子进程等 order_result 期间 poll 投 bars 乱序 → req_id 分流 + 父侧 busy 门控双保险。
3. RPC 超时≠未成交 → 结果未知走对账收敛，禁止重试（req_id 幂等）。
4. 单 worker 网关 vs Kill ≤3s → 优先级队列。
5. 去掉账户镜像会让 get_positions 为空致策略崩 → 保留只读镜像。
6. stop-out/追加保证金由券商执行，父进程只能事后对账发现 → PRD 边界，文档明示。
