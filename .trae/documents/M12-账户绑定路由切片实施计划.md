# M12 模拟盘/实盘按账户绑定路由（多网关节点） 切片实施计划

## Context（为什么做）

用户要求「模拟盘和实盘分别绑定账户/密码/服务器」，并确认要支持**不同账户**（非同一账户语义分离）。

架构事实（探查结论）：
- **MT5 网关单终端单会话**：`MetaTrader5` 包非线程安全、一个终端同一时刻只能登录**一个**账户。
  不同账户 ⇒ 必须在**不同网关节点**（每节点 = 一台机器上的一个 MT5 终端）。
- `MT5Account` 已有 `gateway_node_id` FK（→ `gateway_nodes` 表含 host/port）、`login`、`server`、
  `password_encrypted`（Fernet）。**服务器 = 账户所绑网关节点的 host:port**。
- **实盘已绑账户但没用对**：`LiveRun.account_id` 存在，但运行时所有 `GatewayClient()` 走全局
  `settings.GATEWAY_URL`（忽略 `account.gateway_node_id`），且**不显式登录**——依赖网关 `.env` 的
  `MT5_LOGIN/PASSWORD/SERVER` 自动登录。多节点场景下这会导致连错终端、拿错账户数据。
- **模拟盘完全没绑账户**：`PaperRun` 无 `account_id`，`PaperCreate` 无账户字段，取数走默认网关。
- `GatewayClient()` 裸构造共 12 处：live/manager×5、paper/manager×2、reconcile×1、backtest/queue×1、
  heartbeat×1、accounts 端点（probe 已支持 custom_url）。

**资金安全红线**：本切片改动实盘下单/对账/镜像的网关寻址。核心不变量——**每个 run 的所有网关调用
必须且只能命中该 run 绑定账户所在的节点**，绝不能再落到全局默认地址（否则 A 账户的策略把单下进 B 账户）。

硬约束（沿用）：全中文 UI；MappedAsDataclass 在 DeclarativeBase 前；default_factory；alembic async 迁移；
字面量路由先于 uuid 参数路由；后端无 --reload 改码须重启；PowerShell 用 `;`；emit() 非阻塞渠道派发（M10）。

## 设计

### 路由核心（新增 `services/gateway_route.py`）
- `async def node_url_for_account(db, account_id) -> str`：join MT5Account→GatewayNode，返回
  `http://{host}:{port}`；账户/节点缺失 → 回退 `settings.GATEWAY_URL`（保持单节点旧环境零破坏）。
- `async def account_credentials(db, account_id) -> tuple[login, password, server] | None`：
  解密 Fernet 密码；无密文 → None（调用方决定是否 fail）。
- run 启动时把解析出的 `base_url` 固化进 handle（`_RunHandle.gateway_url`），poll/execute/mirror 复用，
  避免每 tick 查库；节点变更需重启 run 生效（可接受，PRD 无热切节点需求）。

### 实盘（live/manager.py + reconcile.py）
- `start()`：取 `account_id` → 解析 node_url + 解密凭据 → **显式 `client.login(login,pw,server)`**
  （不再依赖 .env 自动登录）→ 后续 symbols/rates 全用该 node_url 构造 client。登录失败 → run fail 带中文原因。
- `_execute_at_gateway` / `_poll` / `_refresh_mirror` / `_gateway_close_all` / kill：
  全部改为用 `h.gateway_url` 构造 `GatewayClient(h.gateway_url)`。
- `reconcile_once()`：按 `account_id` 分组，每组用其节点 client 对账（当前单 client 扫全部 → 错）。
- 单终端冲突守卫：start 时若该节点已被**另一账户**的活动 run 占用 → fail「该网关节点已被其他账户占用，
  MT5 单终端不能同时登录多账户，请为不同账户配置不同网关」。

### 模拟盘（paper）
- `PaperRun` 加 `account_id`（UUID FK→mt5_accounts，**nullable**，ondelete=SET NULL，向后兼容旧行）。
- `PaperCreate` 加 `account_id`（必填）；创建端点校验账户归属（非本人 → 404，同 live 所有权模型）。
- `paper/manager.start()`：解析 account node_url + 凭据 → 显式 login → symbols/rates 用该 node。
  无 account_id（旧行）→ 回退默认节点、跳过 login（保持旧行为不炸）。
- `_poll` 用 `h.gateway_url`。

### 多节点心跳 + 离线告警（gateway_heartbeat / reconcile.offline_watchdog）
- `heartbeat_once`：遍历**所有** GatewayNode 逐个探活写状态（当前只探默认节点）；`ensure_default_node` 保留。
- `offline_watchdog`：改为对「有活动实盘持仓的账户所在节点」判离线（按 node 聚合），而非只看主节点。

### 迁移
- 新 alembic revision（revises=b2c6d9f31a47）：`paper_runs.account_id` add_column（nullable UUID FK）+ index。
- downgrade 反向。

## Phase A — 路由核心 + 实盘改造
1. `gateway_route.py`（node_url_for_account / account_credentials）。
2. live/manager：start 显式 login + handle.gateway_url + 5 处 client 构造改路由 + 冲突守卫。
3. reconcile_once 按账户节点分组。
4. 测试：多节点路由正确（两账户两节点，client.base_url 命中各自节点）、login 失败→run fail、
   冲突守卫、reconcile 分组。全量 pytest + ruff。

## Phase B — 模拟盘绑定 + 迁移
1. PaperRun.account_id + 迁移 + PaperCreate.account_id + 创建端点归属校验。
2. paper/manager：start login + node_url 路由 + _poll；旧行回退。
3. 测试：模拟盘绑账户后取数走其节点、未绑回退默认、归属校验 404、旧数据不炸。pytest + ruff。

## Phase C — 多节点心跳/离线 + 前端
1. heartbeat 遍历所有节点；offline_watchdog 按账户节点。
2. 前端：PaperCreateDialog 加「MT5 账户」下拉（useAccounts，显示 login@server·节点）；
   模拟盘列表/详情显示绑定账户；实盘向导确认已显示节点（复用现有 account 选择）。
3. npm build。

## Phase D — 全量门禁 + E2E
- pytest（≥ 基线+新增）/ ruff / build；重启后端+网关。
- E2E：新建模拟盘选账户 → 详情显示绑定账户与节点；实盘向导账户步显示节点。
- 已知边界：单终端单账户（不同账户须不同节点，同节点多账户运行期冲突会拦截）；节点变更需重启 run。
