# P1 收官：回测「真实点差」第三档（spread_mode=real）实施计划

## Context（背景与目标）

PRD P1 唯一剩余功能项：回测 `spread_mode` 目前只有 `current`（跟随行情，用 MT5 bar 自带点差）/ `fixed`（固定点差）两档，缺第三档「真实点差」——逐根 bar 用 tick 数据推导真实成交价差。本切片补齐该档，目标：

- 用户选「真实点差」后，每根 K 线的成交点差来自该 bar 时间窗内真实 tick 的 `ask−bid` 均值，而非 bar 汇总点差；
- tick 数据缺失的 bar 自动降级（回退跟随行情语义），绝不因 tick 缺失阻断回测；
- 覆盖情况透明化：冻结进 config_snapshot 并在报告页展示。

**核心设计决策**：

1. **数据源**：本地 `tick_data` 表（Tick 数据管理已同步入库，(symbol, time_msc) 主键）。回测子进程无 DB 通道，因此取数必须发生在父进程（queue worker）；网关 `ticks_range` 历史 tick 深度受 MT5 终端限制且不适合逐 bar 回查，不采用。
2. **计算方式**：单条 SQL 按 bar 时间桶聚合：`SELECT time_msc/1000/tf AS bucket, avg(ask−bid) FROM tick_data WHERE symbol=… AND time_msc ∈ [首bar, 末bar+tf) AND bid>0 AND ask>0 GROUP BY bucket`，除以 `point` 换算为点、四舍五入为整数，覆写 `BarArrays.spread`。bar 时间两侧统一 `t // tf_seconds` 对齐（MT5 bar 时间天然按 tf 对齐）。
3. **降级阶梯**：无 tick 覆盖的 bar 保留原 `bar.spread`（即 current 档语义）→ 仍为 0 时引擎按现有逻辑回退 `spread_snapshot`。**FillModel 无需功能改动**——`real` 落入 `spread_points_at()` 现有 else 分支（与 current 同路径），只是 spread 数组值更精准。
4. **Paper/实盘不动**：paper 的 current 档在 on_tick 阶段直接用实时 tick 价差，本身就是真实点差；`schemas/paper.py` 的 SpreadMode 保持 `current|fixed`。
5. **组合回测同步支持**：Portfolio 子任务走同一 queue → 同一 overlay 自动生效，仅扩 `PortfolioCreate` 的 Literal。

## 明确不做（本切片边界）

- paper / 实盘 spread_mode 不扩展（实盘 tick 即真实价差）；
- median 等其它聚合方式（avg 已满足，SQL 原生）；
- 运行期滑点校准、回测-实盘偏差报告（P1 其余独立项）；
- MT5 终端历史 tick 深度限制本身（由降级策略兜底）。
