# 实盘部署后验证清单（M6）

> 适用范围：MT5 量化交易平台「实盘部署 + 风控中心」切片交付后的运维核对。
> 基于实际实现编写：准入四闸 / stdin-stdout RPC 下单中转 / 事前风控 / 5 分钟对账 / 自动降级 / Kill Switch / 链式审计。
> 环境约定：后端 `http://127.0.0.1:8000`，网关 `http://127.0.0.1:8090`，前端 `http://localhost:3000`；API 需 `Authorization: Bearer <access_token>`，网关需 `X-Gateway-Key`。
> 使用方式：每行勾选框后附验证手段（UI 路径 / 命令 / 接口）。标注 🔴 的项失败时**必须立即停止实盘并人工介入**。

---

## 0. 部署前置环境（每次启动实盘前）

- [ ] 🔴 网关健康：`GET http://127.0.0.1:8090/health` 返回 `status=ok` 且 `terminal.connected=true`
  ```powershell
  Invoke-RestMethod http://127.0.0.1:8090/health | ConvertTo-Json -Depth 4
  ```
- [ ] 🔴 MT5 终端已勾选「允许算法交易」：`/health` 中 `terminal.trade_allowed=true`
  - 未开启时所有下单被网关拒绝（retcode 10025/10026 → HTTP 409「终端禁止自动交易」），实盘可运行但无法成交
- [ ] 网关交易白名单包含目标账户：`gateway/.env` 的 `TRADE_ALLOWED_LOGINS`（空=不限制；真实账户上线前必须显式加入）
- [ ] Windows 电源方案：接通电源、睡眠/休眠设为「从不」（实盘结构性前提）
- [ ] 后端实盘开关：`GET /api/v1/live/meta/status` 返回 `enabled=true`
  ```powershell
  Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/live/meta/status -Headers @{Authorization="Bearer $tok"}
  ```

## 1. 准入闸门复核（部署向导内）

- [ ] 🔴 向导第 3 步四闸全绿：权限闸 / 回测闸 / 模拟时长闸 / 记录闸，逐条核对 reason 文案
  ```powershell
  # POST /api/v1/live/wizard/check-admission  body: {strategy_id, version, account_id}
  ```
- [ ] 回测闸指向**拟部署的同一冻结版本**（实盘只接受已冻结版本，工作副本不可部署）
- [ ] 模拟时长闸：`decision_metrics.paper.streak_days ≥ LIVE_ADMISSION_MIN_PAPER_DAYS`（默认 14，可配 7~60）
- [ ] 记录闸：`risk_events_in_window = 0`
- [ ] 部署成功后详情页「准入与配置」Tab 的 `admission_snapshot` 四闸 `passed=true` 已冻结落库
- [ ] 审计含 `admission_pass`（附指标快照）+ `live_deploy`（附规则清单）两条记录

## 2. 启动即时验证（部署后 1 分钟内）

- [ ] 状态 ~15s 内 pending → **运行中**；若 failed 按错误码处置：
  | error_code | 含义 | 处置 |
  |---|---|---|
  | `UNKNOWN_ERROR`+「网关不可达」 | 网关进程未起/网络断 | 检查网关服务 |
  | `UNKNOWN_ERROR`+「无历史数据」 | 品种该周期完全无数据 | 换品种/周期或补数据 |
  | `ILLEGAL_IMPORT`/`RUNTIME_ERROR`+load_failed | 策略装载失败 | 回编辑器修复后重置 |
- [ ] 🔴 账户镜像显示**真实券商数值**（净值/余额/可用保证金非 0.00）
  - 0.00 → 检查 `GET :8090/account` 是否可达（409=MT5 未登录；404=网关版本过旧缺该端点，需重启网关）
- [ ] 「观察期中」提示存在，**单笔上限已填入品种最小手数**（非「—」）、资金上限 = `LIVE_OBSERVATION_CAPITAL_PCT`%
- [ ] `magic` 号已分配且全局唯一（详情页头部可见；对账归属键，重启/恢复不变）
- [ ] 运行日志 Tab 5s 内出现启动/回放记录（时间兜底 flush；持续空白=编排异常）
- [ ] 回放期**无任何成交**：预热窗口订单全部 WARMUP_PERIOD 拒绝（历史绝不触发真实下单）

## 3. 下单执行链路（首个真实信号出现时）

- [ ] 🔴 成交明细 Tab 出现真实 deal：`deal_ticket`/成交价/手数与 MT5 终端「工具箱→交易→历史」**逐笔一致**
- [ ] 订单 comment 携带 `run_id前8位:req_id前8位`（幂等与追溯依据）
- [ ] 信号在运行日志以 `kind=signal` 落库；持仓镜像在下个轮询周期（≤`LIVE_POLL_SECONDS`，默认 10s）更新
- [ ] 拒单场景：策略侧收到结构化错误且**进程不崩溃**：
  | 场景 | 策略收到的 error_code |
  |---|---|
  | 可用保证金不足 | `INSUFFICIENT_MARGIN` |
  | 休市/无当前价 | `MARKET_CLOSED` |
  | 手数越界/无效 | `INVALID_VOLUME` |
  | 价格变动 | `REQUOTE` |
  | 白名单/只读拦截 | `RISK_BLOCKED` |

## 4. 事前风控（建议用测试规则逐项验证）

> 规则管理：`POST/GET/PATCH/DELETE /api/v1/live/rules`（scope: global|account|run，优先级 run>account>global，5s 内热生效）。

- [ ] 单笔最大手数（`max_lot_per_order`）：超限下单被拒且**网关侧零该笔请求**（查网关日志/MT5 历史确认）——这是「发网关前拦截」的核心证据
- [ ] 单日最大亏损（`daily_max_loss`/`daily_max_loss_pct`，action=halt_open_today）：
  - 触发后：后续开仓全部拒绝、**平仓仍放行**；详情页出现「当日停止开仓」黄色提示
  - 次日 UTC 自动解除（`halt_until` 过期）
- [ ] 最大回撤（`max_drawdown`，action=close_all_and_stop）：
  - 触发后：真实全平仓 → 任务停止 → 详情页「已自动降级」徽章 → 账户 `live_allowed=false`
  - 降级后恢复按钮禁用、重新部署被权限闸拦截
  - 仅 admin `POST /live/{run_id}/re-admit`（review_note ≥8 字 + confirm="READMIT" + 二次确认）可恢复，全程审计
- [ ] 频率限制（`max_orders_per_minute`）：连续快速下单触发后按 action 处置
- [ ] `GET /api/v1/live/risk-events` 每条触发均有记录（threshold/observed/action_taken/order 快照）
- [ ] 风控触发会写入 `risk_events(source=paper)` 时阻断对应版本的记录闸（模拟期触发同样计入）

## 5. 观察期（阶梯放量）

- [ ] 观察期内手数/资金上限**只能调低不可调高**（lot_cap / capital_cap_pct）
- [ ] 观察期内触发「当日停止开仓」及以上 → `observation_ends_at` 自动顺延重置（详情页日期变化）
- [ ] 期满且无触发 → 重新走向导可提升至完整配额
- [ ] 观察期内触发「全平仓+停止」级 → 直接自动降级（见第 4 节）

## 6. 控制状态流转

- [ ] 暂停 → 「已暂停」：停止喂新 bar、不再开新仓；恢复 → 「运行中」继续增量
- [ ] 停止（平仓）→ 网关按 `magic` 过滤只平本策略持仓（**不误伤其他策略/手动单**——MT5 终端核对）→ 「已停止」
- [ ] 重置 → 成交/日志清空、仅 `ctx.storage` 存活（状态恢复契约）、重新启动成功
- [ ] 🔴 后端重启后：孤儿 running/paused 任务被 sweep 标 failed（提示「请核对持仓后重新启动」）；重启后**立即执行一次对账**（服务重启期间持仓可能已变动）

## 7. 对账与风险真空

- [ ] 常态：对账周期（`LIVE_RECONCILE_SECONDS`，默认 5min）内平台持仓 vs 网关持仓（按 magic 归属）一致 → 无动作
- [ ] 🔴 人为制造差异（MT5 终端手动平掉一笔策略持仓）→ 下轮对账应发生：
  1. 账户 `trade_frozen=true` → 事前风控拒绝**全部**下单（含 close）
  2. critical 告警「持仓对账不一致，自动交易已冻结」
  3. `risk_events(rule_type=reconcile_mismatch)` + 审计 `reconcile_mismatch`
- [ ] 差异**不会被平台自动平仓**（恢复后仅呈现 diff_tickets 供人工决策——PRD 硬约束）
- [ ] 管理员解冻：`POST /live/accounts/{id}/unfreeze`（confirm="UNFREEZE" + review_note + admin 角色），写入审计 `reconcile_unfreeze`
- [ ] 结果未知订单（网关读超时）→ 详情页「待对账」标记 → 下轮对账一致后自动收敛清除（**绝不自动重试下单**）
- [ ] 网关离线 >`LIVE_GATEWAY_OFFLINE_ALERT_SECONDS`（默认 5min）且存在持仓 → critical 告警「实盘持仓当前无保护」（每段离线只告警一次）；恢复后出现「请核对离线期间持仓」告警

## 8. Kill Switch

- [ ] 双确认交互：首次点击变「再次点击确认熔断」（脉冲），二次点击才执行；「取消」可撤销
- [ ] 执行链与结果：撤挂单 → 平全部持仓 → 停全部策略 → 告警+审计（`kill_switch`），全程 ≤3s
  ```powershell
  # POST /api/v1/live/kill-switch  body: {"confirm": "KILL"}
  ```
- [ ] 优先级队列生效验证：在大量行情轮询进行中触发熔断，仍 ≤3s 完成（交易命令插队于行情之前）
- [ ] 熔断后列表所有活动任务进入终态；`.runtime/live/` 无残留子进程（任务管理器核对 python 进程）

## 附：本次交付已知边界（验证时勿误判为缺陷）

| 现象 | 说明 |
|---|---|
| MT5 未开算法交易开关时所有单被拒 | 预期行为（服务端闸门），非链路故障 |
| 休市/周末时段日志增长慢 | 只有已收盘 bar 才驱动；5s 兜底 flush 保证低流量可见 |
| 实盘成交明细与回测价格不一致 | 三态一致原则落点在**信号层**；实盘成交价=市场真实价，本就不应相同 |
| stop-out/追加保证金由券商执行 | 平台不感知，只能事后对账发现（PRD 明示边界） |
| 网关重启后镜像才恢复真实数值 | `GET /account` 端点随 M6 新增，旧网关进程无此路由（404→镜像 0.00） |
