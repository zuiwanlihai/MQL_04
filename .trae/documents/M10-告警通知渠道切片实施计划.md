# M10 告警通知渠道（邮件 + Webhook） 切片实施计划

## Context（为什么做）

PRD M7「MVP 渠道：站内 + 邮件；P1 加 Telegram / 钉钉 / 企业微信 Webhook」。
现状：[alert.py](file:///e:/SRE/mql/MQL_04/backend/app/services/alert.py) 的 `emit()` 只写站内行，邮件是 logged no-op，
`alert_events.emailed_at` 字段早已预留；M6/M7 验证清单均把「邮件渠道」列为真实资金上线前置项。
`emit()` 是唯一告警入口（reconcile / manager / audit 共 6 个调用方），渠道扇出必须集中在此。

**核心约束（资金安全）**：`emit()` 被 kill-switch、对账、降级等关键路径 await——
任何渠道发送**绝不能阻塞** emit 主流程。方案：站内行照旧同步落库；网络渠道走
`asyncio.create_task` fire-and-forget，失败只记日志不抛出。

**零新依赖**（backend venv pip 已损坏）：邮件用 stdlib `smtplib` + `asyncio.to_thread`；
Webhook 用已装的 `httpx`（10s 超时）。

硬约束（沿用）：全中文 UI；字面量路由先于 uuid 参数路由；PowerShell 用 `;`；后端无 --reload 改码须重启；
密钥（SMTP 密码/Webhook URL）只进 .env，绝不回显到任何 API 响应。

## 设计

### 渠道模型（per-user 订阅 + 全局 SMTP）
- 新表 `notification_channels`：`user_id` FK、`kind`（email|telegram|dingtalk|wecom）、
  `target`（邮箱地址 / Bot 令牌+chat_id 拼接串 / webhook URL，**响应中脱敏**）、
  `min_level`（info|warn|error|critical，达到该级别才发）、`enabled`、`verified_at`（可空）。
- 全局 SMTP：`settings.SMTP_HOST/PORT/USER/PASSWORD/FROM` + `SMTP_TLS`；未配置 → 邮件渠道测试时明确报「未配置」。
- `emit()` 落站内行后：查启用渠道 → 按 min_level 过滤 → 逐渠道 create_task 发送；
  email 成功回写 `alert_events.emailed_at`（字段已存在）。

### 端点（`/notify` 前缀，登录用户可用）
- `GET /notify/channels`（本人列表，target 脱敏）、`POST /notify/channels`、
  `PATCH /notify/channels/{id}`、`DELETE /notify/channels/{id}`
- `POST /notify/channels/{id}/test`：发一条测试告警到该渠道（email 走 SMTP、webhook 走 httpx post），
  返回成功/失败中文信息；email 成功即置 `verified_at`
- 渠道增删改 + 测试均写审计（`channel_change` / `channel_test`，PRD M7 ①「权限开关变更/配置变更」）

### 发送器（`app/services/notify/`）
- `email.py`：`send_email(to, subject, body)` — smtplib SMTP/SMTPS，`asyncio.to_thread` 包装，10s 超时
- `webhook.py`：`send_telegram/send_dingtalk/send_wecom(target, title, message, level)` — httpx，payload 各家格式
- `dispatcher.py`：`dispatch(row, channels)` — 逐渠道 create_task + 异常吞噬 + 成功回写 emailed_at
