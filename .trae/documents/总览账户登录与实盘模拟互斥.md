# 总览账户登录 + 实盘/模拟互斥

## Context

平台当前网关固定登录 Demo 91350（gateway/.env 默认），总览页无账户状态展示。需求（用户已确认两项决策）：

1. **总览页添加「MT5 账户登录」**：交互形态 = 切换已绑定账户（显示当前登录账户 + 已绑定账户下拉 + 一键切换，凭据复用 MT5Account 加密存储，无需重输密码）
2. **实盘/模拟互斥（前端+后端双保险）**：登录实盘账户 → 模拟盘禁用；登录模拟账户 → 实盘禁用。前端置灰+提示，后端创建/启动校验 409 防绕过

关键事实（已探明）：网关已有 `POST /account/login` 端点（mt5_client.py `_login_sync` L279）；但 `client.login` 成功后不记忆凭据，`_ensure_initialized_sync`（L226-231）重连时按 .env 强制切回 91350——**切换登录后任何 IPC 重连都会静默切回默认账户，这是唯一必须改网关的点**。MT5Account.account_type（demo|real|contest）为判定源；paper.py 创建无类型校验。

## 实施步骤

### 第 1 步：网关 override 凭据（先行，后续依赖它）
`gateway/app/mt5_client.py`：
- `__init__` 加 `self._login_override: tuple[int, str, str] | None = None`
- `_login_sync` 成功后写入 override
- `_ensure_initialized_sync` 凭据选择改为 `override or (.env 三元组)`，注释说明原因
- `_logout_sync` 清空 override
- 风险接受：网关进程重启 override 丢失回退 .env 默认（不持久化密码到磁盘），靠第 2 步实时探活纠偏
- 网关测试：新增单测覆盖 override 记忆/清空/重连复用

### 第 2 步：后端 activate / active 端点
`backend/app/api/v1/endpoints/accounts.py`：
- `POST /accounts/{id}/activate`：归属 404 → `gateway_route.account_credentials()` 解密 → `resolve_gateway()` 取节点 URL → httpx POST `{gw}/account/login`（**timeout ≥60s**，mt5.login 含终端重连很慢）→ 失败 409 透传中文 detail → 成功 `audit.record("account_activate", ...)`（actor 构造参照 live.py `_actor`）
- `GET /accounts/active`：对账户涉及节点（含默认 `settings.GATEWAY_URL`）GET `/health`，聚合返回 `[{node_id, account:{login,type,server}|None}]`，不落库
- pytest：activate 成功（mock httpx）/网关失败/解密失败；active 聚合

### 第 3 步：创建端点类型互斥（后端侧双保险）
- `paper.py` `create_paper_run`：绑定账户 `account_type != "demo"` 或活跃网关账户 type=="real" → 409「模拟盘仅支持模拟账户，当前登录的是实盘账户」
- `live.py` `deploy_live_run`：`acct.account_type != "real"` → 409；`services/live/admission.py` 权限闸同帧校验（防绕过创建直连）
- pytest：类型不匹配 409（paper/live 各一）+ admission 闸

### 第 4 步：前端 hooks 与类型
- `frontend/src/types/api.ts`：加 `ActiveAccountInfo`
- `frontend/src/hooks/useAccounts.ts`：仿现有模式加 `useActiveAccount`（refetchInterval 15s、网关不可达静默 null）+ `useActivateAccount`（onSuccess invalidate accounts/active-account 相关键）

### 第 5 步：Dashboard 登录卡片 + 侧栏禁用
- 新组件 `frontend/src/components/account/ActiveAccountCard.tsx`（Dashboard.tsx L127 统计卡片区旁）：当前登录账户 + 类型徽标（real 红/demo 绿）+ 已绑定账户下拉 + 切换按钮；切换前确认提示「切换登录将中断行情约 5-10 秒」；pending 禁用；409 toast 透传
- `frontend/src/components/layout/AppShell.tsx` L36-40：PAPER_NAV/LIVE_NAV/MANUAL_NAV 按 activeType 置灰（real→paper 禁、demo→live/manual 禁）+ tooltip 原因
- vitest：ActiveAccountCard 禁用逻辑

### 第 6 步：门禁 + E2E
- backend：pytest 全量 + ruff check；frontend：tsc --noEmit + vitest run + npm run build
- 浏览器 E2E：总览显示 91350（demo 徽标）→ 实盘入口置灰有提示；切换流程确认框 + loading + 完成后类型翻转
- **关键回归**：切换登录后杀 MT5 终端进程待 watchdog 拉起，GET /health 的 account.login 仍为切换账户（验证 override 生效）；品种列表随账户宇宙自动变化（demo 62 无后缀 / live 58 .E）
