# 行情页实时化切片实施计划

> 日期：2026-10-12 ｜ 需求（用户原话）：「行情页，数据来源 MT5，但是不依赖 MT5 终端，终端不启动也要能拿到数据，tick 级别刷新」
> 用户已拍板：实现路径 = **Python 网关托管后台终端**（自动拉起 + 自动登录 + 自愈，用户无感）；tick 级刷新 = **WS 推送**

## 1. 概述与价值

- 行情页从「5s 轮询」升级为「WS 实时推送」：报价变化亚秒级到达，推送粒度 = 每品种最新 tick 快照（bid/ask/last/time_msc 变化即推）
- 「不依赖终端」：MT5 行情必须经终端进程（MetaTrader 5 Python API 事实约束），采用网关托管——终端未启动时 TerminalGuard 自动拉起终端 + 网关启动自动登录（gateway/.env 四项已配），用户全程无感
- **不做**：逐 tick 流（copy_ticks_from 游标模式，为单品种深度行情预留，本次不实现）、跨连接共享扇出优化（泵天然全局去重，多标签页各自订阅即可）、K 线图实时化（useKlines 维持手动刷新）

## 2. 传输选型（已定）

| 候选 | 结论 |
|---|---|
| SSE | 可行但单向，重连/订阅管理均需自造 |
| **WebSocket** | ✅ 双向（subscribe/unsubscribe 协议）、浏览器/FastAPI 原生支持；断线重连 + 轮询回退在前端 hook 统一处理 |

- WS 认证：浏览器 WS **无法自定义 header** → 一次性 ticket 方案：`POST /api/v1/market/ws-ticket`（常规 JWT 认证）换 30s TTL 单次使用 ticket → `WS /ws/quotes?ticket=…` 连接。避免 JWT 裸进访问日志。

## 4. 方案设计

### 4.1 后端：QuoteHub + 推送泵 + WS 端点

- `services/quote_push.py` — QuoteHub 单例：
  - 订阅注册表：conn→set[symbol] 与 symbol→set[conn] 双向索引；`union(symbols)` 全局订阅集
  - **惰性泵**：无订阅者不请求网关；有订阅者按 `MARKET_PUSH_POLL_SECONDS`（默认 0.5s）调 `gateway.quotes(union)`
  - 变化检测：与上次快照比对（bid/ask/last/time_msc 任一变化），**变化品种才广播**（休市自然安静）
  - 网关失败：广播 `{"type":"gateway_error","detail":…}` 帧并指数退避（1s→10s 封顶），**不踢客户端不自杀**，恢复即续推
- WS 端点 `WS /ws/quotes`（app 级路由，不走 /api/v1 前缀，复用 vite /ws 代理）：
  - 连接即认证：`?ticket=` 校验（30s TTL、单次使用、内存 dict，用后即焚）
  - 客户端→服务端：`{"action":"subscribe","symbols":[…]}` / `{"action":"unsubscribe",…}`；单连接上限 50 品种（与 REST 对齐，超限拒绝该帧并回 error）
  - 服务端→客户端：`{"type":"subscribed","symbols":[…]}` 确认；`{"type":"quotes","items":[QuoteOut…]}`（**与 REST QuoteOut 同构，前端类型零改动**）；`{"type":"ping"}` 每 15s keepalive（区分「休市无变化」与「假死连接」）
  - 断开清理：双向索引移除、union 重算；慢客户端 send 异常即丢弃并清理，不阻塞整泵
- ticket 端点 `POST /api/v1/market/ws-ticket`：常规 JWT 认证，返回 `{ticket, expires_in}`
- config 新增：`MARKET_PUSH_ENABLED` / `MARKET_PUSH_POLL_SECONDS`(0.5, ge=0.2) / `MARKET_PUSH_MAX_SYMBOLS`(50)
- lifespan 启停（照 heartbeat 模式，cancel + suppress CancelledError）

### 4.2 前端：useQuotesStream + 降级链

- 新 hook `hooks/useQuotesStream(names)`：WebSocket 订阅维护 quoteMap；导出连接状态 `'connecting' | 'live' | 'polling' | 'error'`
- **降级链**：WS 断开/失败 → 指数退避重连（1s→30s 封顶）→ 重连期间回退现有 5s 轮询（复用 useQuotes 逻辑）→ WS 恢复自动停轮询
- ticket 401：走 `refreshAccessToken()` 后重试一次，仍失败回退轮询
- MarketOverview：连接状态点（绿=实时推送 / 黄=轮询降级 / 红=不可用）+ 文案改「MT5 网关 · tick 级实时推送」
- QuoteTable 不改（数据同构）

### 4.3 托管终端验证（无新代码，冒烟确认）

- 场景：**手动关闭 MT5 终端** → ≤30s guard 拉起 → 自动登录恢复 → `/quotes` 恢复可用 → WS 客户端经历 gateway_error 帧后恢复收 quotes
- 终端从未启动的冷启动场景一并验证（gateway initialize/拉起路径）
- 若 guard 拉起后自动登录偶发失败：网关已有 `_ensure_initialized` 重试兜底；不满足时另行补强（本切片仅记录，不预留代码）

## 7. 关键坑位备忘

- 浏览器 WS 不能带 Authorization header → **ticket 而非裸 JWT**（防 access log 泄 token）；ticket 内存态，backend 重启即失效，前端断开自动重取
- vite `/api` 代理**无 ws:true** → WS 必须走 `/ws` 前缀（已配好）；若日后改 `/api/v1/…/ws` 需同步改 vite 代理
- 休市/无变化时 WS 静默 ≠ 断线：服务端 15s ping keepalive；前端**仅以 onclose/onerror 触发重连**，勿用「超时无消息」判死
- 泵失败不踢客户端：gateway_error 帧 + 前端黄点提示，恢复即续推；泵指数退避防打爆网关
- 50 品种上限单连接与 REST 对齐；多标签页=多连接各自订阅（泵按 union 去重，网关压力不随连接数增长）
- QuoteHub 进程内存态 → backend 必须 uvicorn 单 worker（现状即单 worker）
- MT5 启动→登录完成有 20–60s 窗口，期间 `/quotes` 可能 MT5Error：泵按 GatewayError 退避，属预期非 bug
- 每连接 send 在事件循环内逐个执行：单连接慢/死用 try/except 即时清理，绝不阻塞整泵
